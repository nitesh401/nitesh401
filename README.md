## Engineering principles

- **Boundaries first.** Controllers handle HTTP, services hold rules, repositories talk to the database. Mixing them is where maintenance cost starts.
- **Validate at the edge.** Treat every API input as untrusted and fail early with clear error responses.
- **Be deliberate with transactions.** Know the isolation level, the lock scope and what happens under concurrent writes.
- **Design for failure.** Timeouts, retries with limits, idempotent consumers, and enough logging to explain what happened.
- **Events over coupling.** Where it fits, publish facts through Kafka instead of calling services in chains, and accept eventual consistency knowingly.
- **Security is part of the design.** Delegate identity to a standard provider (OAuth2/OIDC, Keycloak) rather than inventing it.
- **Tests that earn their keep.** Fast unit tests with JUnit and Mockito, plus integration tests at the seams that matter.

## AI-assisted development

I use **Claude Code** and **GitHub Copilot** as working tools, mainly for:

- drafting and extending unit tests
- refactoring and code review second opinions
- exploring unfamiliar code and generating boilerplate

AI output gets reviewed like any other code: it has to pass the tests, fit the design and be something I can explain.
